# Сборка готового OVA-образа учебной ВМ

Эта папка собирает **единый OVA-образ** виртуальной машины, которая
загружается сразу в **уязвимом состоянии**:

- уязвимое ядро Linux (Dirty Pipe, CVE-2022-0847) - базовый образ Ubuntu
  21.10 с ядром 5.13;
- устаревшая система печати **CUPS** (CVE-2024-47076/47175/47176/47177),
  cups-browsed запущен и принимает удалённые анонсы;
- все четыре скрипта уже внутри ВМ: `check_vuln.sh`, `fix_vuln.sh`,
  `check_dirtypipe.sh`, `fix_dirtypipe.sh`.

Преподаватель импортирует OVA, обнаруживает уязвимости скриптами, затем
закрывает их самостоятельно.

> ⚠️ Только изолированная учебная среда. Рабочего эксплойт-кода внутри нет -
> только средства обнаружения и устранения.

## Почему OVA не приложен готовым файлом

Сборка загрузочного OVA требует **запуска виртуальной машины** (установка
ОС и экспорт диска), то есть аппаратной виртуализации (KVM/VirtualBox).
Среда, в которой готовился отчёт, виртуализацию не предоставляет, поэтому
собрать и, что важно, **проверить загрузку** OVA там невозможно. Ниже -
готовый однокомандный сценарий сборки на обычном компьютере.

## Требования (локальная машина)
- VirtualBox (с включённой виртуализацией VT-x/AMD-V в BIOS);
- Vagrant.

## Сборка одной командой
```bash
cd ova-build
./build_ova.sh          # Linux/macOS
# или вручную:
vagrant up
vagrant halt
VBoxManage export os-security-lab --output os-security-lab.ova --ovf20
```
На выходе - файл `os-security-lab.ova` (несколько ГБ). Его и передают
преподавателю.

## Импорт у преподавателя
VirtualBox → Файл → Импорт конфигураций → выбрать `os-security-lab.ova`.
Логин/пароль стандартные для Vagrant-бокса: `vagrant` / `vagrant`.

## Работа внутри ВМ
```bash
check_vuln.sh            # уязвимое состояние CUPS
check_dirtypipe.sh       # уязвимость ядра
sudo fix_vuln.sh         # закрыть CUPS
sudo fix_dirtypipe.sh    # обновить ядро
sudo reboot
check_vuln.sh && check_dirtypipe.sh   # убедиться, что закрыто
```

## Если образ ubuntu/impish64 недоступен
impish (21.10) снят с поддержки. Подойдёт любой базовый бокс с ядром из
диапазона 5.8-5.16.10. Варианты: заменить в `Vagrantfile` строку
`config.vm.box` на `generic/ubuntu2110`, либо на `ubuntu/focal64` c
последующей установкой уязвимого ядра 5.13 из HWE. Исправленными считаются
ядра >= 5.10.102 / 5.15.25 / 5.16.11 - это проверяет `check_dirtypipe.sh`.
